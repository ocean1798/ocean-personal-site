# Lenis 决策证据

- 假设：只有当桌面首屏存在明确滚动叙事，并且平滑滚动不破坏原生导航契约时才值得引入 Lenis；手机始终使用原生滚动。
- 命令：`npm run build:lenis`；静态审查 `experiments/lenis/main.ts`、`src/styles.css` 与首屏锚点。
- 结果：构建 exit 1，原因是无权覆盖原实例的 `dist/lenis`。既有 gzip 报告记录最小 Lenis 实验为 6,537 B（6.38 KiB）。当前首屏只有“继续看看”原生锚点和普通页面滚动，没有必须由惯性滚动表达的多幕叙事。按任务约束，本轮未启动浏览器，因此滚轮、触控板、返回、Home/End、PageUp/PageDown、方向键与焦点定位没有动态验证。
- 结论：`reject`（后续出现真实桌面滚动叙事时再评估）。现阶段收益不足，保留原生滚动、锚点、键盘与焦点契约。
